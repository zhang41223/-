================================================================

### 1.1 错误 [3条]

[ERR-RENT-01] 图片读取失败 → 用例脱离实际UI
  根因: 截图上传失败，系统无法读取
  规则: 生成用例前先确认图片是否成功上传；失败则要求用户文字描述UI元素

[ERR-RENT-02] 全局字符串替换产生语法错误
  案例: "FCP < 2秒(2000ms)(2000ms)" 重复替换；"流畅度"被拆分
  规则: 禁止全局字符串替换改写内容；用正则词边界(\b)或逐句分析

[ERR-RENT-03] 中间版本文件堆积
  规则: 同一文件直接修改，禁止生成多版本中间文件

### 1.2 遗漏 [12条]

[MISS-RENT-01] Core Web Vitals: 缺LCP≤2.5s / CLS≤0.1 / INP≤200ms
[MISS-RENT-02] SSR失败降级CSR / Hydration不匹配闪烁
[MISS-RENT-03] CDN故障: 旧版本返回 / 503故障 / 跨区域不一致
[MISS-RENT-04] 浏览器插件冲突: 广告拦截 / 密码管理器 / 深色模式
[MISS-RENT-05] SEO进阶: Schema.org JSON-LD / 面包屑Schema / 收录摘要
[MISS-RENT-06] 社交分享卡片: 微信/QQ预览 / Twitter/Facebook OG适配
[MISS-RENT-07] 多语言RTL: 阿拉伯语翻转 / 英文标题溢出30%
[MISS-RENT-08] A/B测试: 对照组一致性 / 分流比例验证
[MISS-RENT-09] 数据埋点: 曝光/点击事件 / 参数完整性
[MISS-RENT-10] 保护入口: 客服 / 申诉 / 未成年人保护/实名认证
[MISS-RENT-11] 支付安全: HTTPS证书 / 二次验证(短信/指纹)
[MISS-RENT-12] 图片版权: 自动水印 / 盗图举报下架

## 2. 优惠券V2.0 (2026-07-17)
================================================================

### 2.1 错误 [8条]

[ERR-CPN-01] 统计硬编码≠实际: P0标12实际13，P1标14实际16
  规则: 统计数据必须从cases字典动态遍历计算，禁止手写

[ERR-CPN-02] 文件锁定→PermissionError崩溃
  规则: 文件输出脚本必须内置降级: 先存目标→失败存_tmp→提示用户替换

[ERR-CPN-03] P0占比24%过高 (13/54)
  P0标准: 仅限①资金安全风险 ②数据不可恢复 ③核心状态机破坏
  规则: P0数量控制在总用例10%-15%以内

[ERR-CPN-04] 图片读取再次失败 (docx内5张PNG，634KB超64KB限制)
  规则: docx图片先提取单独读取；超限则压缩或分段；主动告知用户失败

[ERR-CPN-05] 后端校验术语不统一: "二次校验"/"状态机校验"/"RBAC校验"/"唯一索引"
  标准术语库:
    输入校验 → "后端参数校验(必填/格式/范围)"
    状态校验 → "后端状态机校验(状态流转合法性)"
    权限校验 → "后端权限校验(RBAC角色校验)"
    并发校验 → "后端并发校验(乐观锁/分布式锁)"
    唯一性   → "后端唯一性校验(唯一索引)"

[ERR-CPN-06] 缺跨模块联动: 券-订单抵扣 / 券-退款返还 / 券-用户券包 / 券-营销互斥
  规则: 后台功能测试必须覆盖跨模块数据流，至少覆盖券-订单、券-退款

[ERR-CPN-07] PowerShell命令被用户跳过
  规则: 文件操作统一用Python标准库(os/shutil)，不依赖PowerShell

[ERR-CPN-08] 用例编号跳跃 (插入式编号导致不连续)
  规则: 新增用例在各模块末尾追加编号，禁止中间插入

## 5. 行动计划汇总 (按优先级)
================================================================

### P0-高优 (生成用例前必须执行)
A1. 逐字核对需求文档: 触发条件/时机/计算基数/金额边界，禁止臆断
A2. 资金链路全覆盖: 发放+回退(退款/撤销/冲正) + 续费/转租衍生场景
A3. 退款场景枚举: 正常退款 + 业务规则定义的全部特殊退款原因
A4. 可见性断言: 测试"不可见"而非仅测"可见"
A5. 佣金基数验证: 明确含/不含项(如押金排除)

### P1-中优 (生成时必须执行)
B1. 统计数据动态计算: 从用例列表遍历统计，禁止手写聚合数值
B2. P0占比控制: ≤15%，超出则降级非资金安全类为P1
B3. 用例合并: 同操作多对象→多断言; 边界值→子步骤; 字段覆盖→一条列全部
B4. 跨模块查重: 全量范围内去重，非单模块内部
B5. 模块最小用例数≥5条
B6. 用例编号末尾追加，禁止中间插入

### P2-低优 (环境与流程优化)
C1. 图片获取降级: docx提取图片单独读取 → 超限压缩 → 引导文字描述
C2. 文件输出降级: PermissionError → 存_tmp → 提示替换
C3. 文件操作用Python(os/shutil)，不依赖PowerShell
C4. 术语标准化: 后端校验/埋点事件/状态机统一命名
C5. 单文件迭代修改，禁止多版本堆积

## 6. AI生成用例强制检查清单 (生成后自检)
================================================================

□ [触发条件] 是否逐字核对需求文档中的触发时机?
□ [资金链路] 发放场景是否同步覆盖回退(退款)链路?
□ [计算基数] 金额计算是否验证了含/不含项边界?
□ [衍生场景] 是否覆盖续费/转租/续约等生命周期衍生?
□ [特殊退款] 是否枚举了业务规则中的全部特殊退款原因?
□ [可见性]   权限类需求是否测试了"不可见"断言?
□ [去重]     全量范围内是否有重复/高度相似用例?
□ [合并]     同操作多对象/边界值/字段覆盖是否已合并?

L27. 生成用例后必须对照通用自查清单核查遗漏(搜索/筛选/分页/排序/防抖/长文本/资源失败/脱敏/动态变化/导出安全)

L35. [强制规则] 文件更新后必须主动杀死编辑器进程(taskkill /F /IM notepad.exe)，不可依赖用户手动关闭。根因: 记事本会复用已打开窗口显示旧版缓存，即使磁盘已是最新版，用户打开仍看到旧版。永久解决: 每次ok指令导入文件后，自动执行杀死notepad进程，确保用户下次打开加载最新内容。不可仅依赖fsync/原子替换/清缓存，因编辑器层缓存独立于文件系统
